# 演示视频制作脚本（5-8 分钟）

> 对应赛项要求：MP4、1080p 及以上、普通话讲解、时长 5-8 分钟，展示核心功能与创新点。
> 提交前自查：分辨率 ≥1920×1080、帧率 ≥30fps、声音清晰无底噪、文件 <500MB（过大用 H.264 二压）。

## 一、录制前准备清单

- [ ] 后端以 `run.bat` 或 `mvnw spring-boot:run` 冷启动一次，确认一键可跑（这正是评分点）
- [ ] 浏览器开新 Profile，**隐藏书签栏/下载记录/其他标签页**，缩放 100%
- [ ] 预登录三个角色（管理员/用户各开一个浏览器 Profile），避免录到输密码
- [ ] 预置好演示数据：至少 3 条订单、几条评论、茶道AI 已有对话历史
- [ ] 确认右上角状态灯显示「大模型在线」；若录离线兜底段落则故意断网/去 Key
- [ ] OBS/captura 录制 1080p，先录 30 秒试听音量
- [ ] 手写一份台词卡（本文分镜的"口播"列），**不要照读**，练到能脱稿

## 二、分镜脚本（总长约 6 分 30 秒）

| 时间 | 画面 | 操作 | 口播要点 |
|---|---|---|---|
| 0:00-0:30 | 登录页 | 缓慢滑过左右两栏 | 一句话定位："茶文化管理系统，一个内容+电商+AI 的完整平台。我们不做 AI 套壳，把大模型能力融进了检索、决策、数据分析三个层面。" |
| 0:30-1:10 | 前台首页 | 滚动展示 hero、栏目入口；点「问问茶道AI」 | 强调整站设计语言统一；顺势进入主题 |
| 1:10-2:20 | 茶道AI 对话 | 问「新手喝什么茶不容易失眠？」；等流式回答；**点击回答下方的引用来源卡**，跳转原文 | 重点讲三件事：流式输出、引用可溯源、回答基于站内知识库而非大模型裸答 |
| 2:20-3:10 | 茶道AI Agent | 问「我上次买的龙井怎么样？再推荐一款类似的」；展示时间线：思考→调用查订单工具→调用推荐工具→结果 | 口播："ReAct 工具调用循环，模型自己决定调几次工具；推荐结果可以直接加购，AI 和业务是闭环的" |
| 3:10-3:40 | 多模态 | 上传一张干茶照片，问「这是什么茶」 | "图片理解接入了 Agent 决策链路，不只是看图说话" |
| 3:40-4:40 | 管理端 · RAG 评测 | 登录管理台 → RAG 评测 → 点「快速验证（前 8 题）」→ 等表格出结果 | 口播："我们不靠感觉调 prompt——70 题评测集（覆盖 200 条知识库），三种检索策略消融对比，Recall@3 和 MRR 摆在表里，检索质量是可度量的" |
| 4:40-5:20 | 管理端 · 自然语言查数 | 输入「哪种茶卖得最好？」→ 出条形图；再点一个示例问题 | "运营不用写 SQL，中文提问直接出统计图，意图解析失败有关键词兜底" |
| 5:20-5:50 | 管理端 · 数据管理 | 搜模块、改一条商品、保存（toast 出现即可） | 快速带过 25 个模块的通用管理能力，证明系统完整度 |
| 5:50-6:20 | 离线兜底 | 断网或换未配 Key 的配置，刷新茶道AI，发一句话 | "评审环境没有外网也能跑：自动降级为 BM25 检索+本地推荐，功能链路不中断" |
| 6:20-6:50 | 收尾 | 回到首页定格 | "技术栈与分工见技术文档，代码仓库与本文档同步提交。谢谢观看。" |

## 三、翻车点提醒（每一条都是真实事故高发区）

1. **AI 回答等待时间**：录制前先跑一遍同样的问题让向量缓存热起来，避免录屏里干等 30 秒。
2. **评测功能全量跑要 2-5 分钟**：只录「前 8 题」快速档；全量结果可以提前跑好后展示历史表格。
3. **不要现场输入密码**，不要露出任何 API Key（包括 IDEA 配置界面、环境变量窗口）。
4. 修改数据类演示（编辑/删除）**只演示一次且用测试数据**，避免把种子数据改乱。
5. 断网演示段：录完立刻恢复网络，防止后面素材同步出问题。
6. 视频里出现的所有 URL 必须是 `localhost` 或正式演示域名，不能带个人路径。

## 四、剪辑与封装

- 剪掉等待片段时用「加速 4x + 字幕"实时生成中"」，不要硬剪黑帧
- 关键结论配字幕条（如"Recall@3 = 0.87"），评委静音看也能懂
- 导出：H.264 / 1080p / 30fps / AAC 192kbps，命名 `队伍名-作品名-demo.mp4`
