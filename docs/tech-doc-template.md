# 技术文档写作模板（导出 PDF，≤30 页）

> 用法：把每个「◎写什么」替换成正文即可；页数预算是建议值，允许 ±20%。
> 写作总原则：图 > 表 > 文字；每一章回答一个评委问题，不写教科书式的铺垫。

| 章节 | 页数 | 回答评委的什么问题 |
|---|---|---|
| 封面+目录 | 1 | 作品叫什么、谁做的 |
| 一、作品概述 | 1.5 | 这是个什么东西，解决什么问题 |
| 二、需求与功能设计 | 2.5 | 功能是否完整、边界是否清晰 |
| 三、系统架构 | 3 | 技术栈与模块划分是否合理 |
| 四、AI 能力设计（重点） | 6 | AI 是深度集成还是套壳？ |
| 五、AI 质量评测 | 2.5 | 效果有没有证据？ |
| 六、数据与安全设计 | 2 | 有没有工程素养？ |
| 七、创新点 | 1.5 | 凭什么比别人好 |
| 八、团队分工 | 1 | 是不是真团队开发 |
| 九、部署与复现手册 | 2 | 评委自己能不能跑起来 |
| 十、总结与展望 | 1 | 有没有清醒的自我认知 |

## 各章写作模板

### 一、作品概述
◎写什么：一段话定位（茶文化领域的内容+电商+AI 平台）；目标用户三类角色各一句；一个「传统方案 vs 本作品」对照表（普通商城+人工客服 vs 知识库问答+Agent 导购+自然语言查数）。

### 二、需求与功能设计
◎写什么：用例图一张；功能清单表（模块/角色/一句话说明，直接抄 README 的模块对照表）；**只展开写 2 个核心流程的时序图**：①茶道AI 一次问答的全链路 ②下单流程。其余功能一句带过，不要流水账。

### 三、系统架构
◎写什么：分层架构图一张（前端 Vue / 管理端静态页 / Spring Boot 控制层 / 服务层 / MyBatis / MySQL + 外部 DeepSeek & DashScope API）；技术选型表加一列「为什么选它」；模块包结构树。★★ 在此章加一小节「工程基座说明」：诚实写明系统基于通用教学脚手架二次开发，本团队的工作集中在 AI 服务层、检索引擎、管理端界面重构与安全整改（详见 Git 提交历史）。**主动交代比被评委问出来强。**

### 四、AI 能力设计（全文最重要的一章）
◎写什么：
1. **RAG 混合检索**：画检索流水线图（问题 → BM25 稀疏召回 + DashScope 稠密向量 → RRF 融合 → LLM 语义重排 → 拼装 Prompt 带引用 → 流式回答）；配一张向量库/知识表结构说明；解释为什么单一检索不够（关键词命中 vs 语义近义）。
2. **ReAct Agent**：贴一张工具清单表（查订单/推荐商品/检索知识/泡茶指南/推荐讲座）；贴一次真实的多轮工具调用日志（脱敏），说明「模型自主规划调用次数」。
3. **多模态**：图片如何进入决策链路（上传→理解→并入对话上下文）。
4. **NLQ 自然语言查数**：意图解析→受限 SQL 白名单→图表渲染；强调「只允许四种白名单统计，不拼接自由 SQL」防注入。
5. **降级设计**：无 Key/无网时的 BM25+本地推荐链路，说明这是为评审环境专门设计。

### 五、AI 质量评测
◎写什么：评测集构成表（题量/覆盖的茶类主题）；三策略对照表直接贴管理端截图（BM25 / 混合 / 混合+重排 的 Recall@3 与 MRR）；一段结论（混合+重排相对纯稀疏的提升幅度）；**一段限制说明**：当前语料 200 条（种子 160 + 站内 40）仍属演示规模，扩容计划见第十章。

### 六、数据与安全设计
◎写什么：核心表关系图（用户/茶商/商品/订单/AI 知识库）；安全清单（BCrypt 密码、登录后透明升级、@IgnoreAuth 收紧、SQL 白名单、上传后缀白名单、CORS 白名单、fastjson 升级）——这些 2026-09 整改在 Git 历史里都有对应提交，**逐条附上提交哈希**，这是过程真实性的最好证据。

### 七、创新点
◎直接引用 `docs/innovation-points.md` 的前 4 条，每条一段话+一张配图，不要粘贴全文。

### 八、团队分工
◎写什么：每人一行（姓名/职责/核心贡献），用 Git 提交作者名对得上；明确写「AI 服务层/检索引擎/评测体系」等关键模块的负责人。

### 九、部署与复现手册
◎写什么：三条命令的极简手册（数据库初始化 → 后端启动 → 访问入口），直接引用 README；附「常见失败排查」表（端口占用/JAVA_HOME/Key 未配置时的降级表现）。

### 十、总结与展望
◎写什么：三条已完成 + 三条诚实的限制（语料规模、支付为模拟、脚手架基座）+ 下一步计划。**评委对清醒的自我认知评价很高，对吹牛很反感。**

## 排版与提交

- 工具：Markdown 写完用 Typora/VSCode 插件导出 PDF；架构图用 draw.io 或 excalidraw，**导出 PNG 后插入**，不要贴代码截图当代替
- 字号：正文 11pt，图注 9pt；所有截图统一 1080p 裁剪
- 导出后自查：目录页码对不对、图是否糊、有没有漏团队名
